# 부산 한 조각 v1.1.0

여행의 일정과 지출을 한곳에 기록하는 설치형 웹앱(PWA)입니다.
2026년 10월 24–25일의 사진 속 일정 20개가 들어 있습니다.
별도 서버, API 키, 패키지 설치, 빌드 작업 없이 GitHub Pages에서 사용할 수 있습니다.
Android APK가 아닌, 브라우저에서 홈 화면에 추가하는 웹앱입니다.

## 이번 버전: 선택형 컬러 테마

상단의 팔레트 아이콘 또는 설정에서 **나의 여행 색감**을 선택하세요.

| 테마 | 라이트 | 다크 |
|---|---|---|
| 로즈 크림 | 연분홍·로즈골드·크림 | 딥 로즈·웜 플럼·로즈골드 |
| 올리브 네이비 | 짙은 올리브그린·네이비·크림 | 미드나이트 네이비·올리브·웜 크림 |

화면 밝기는 **라이트 / 다크 / 기기 설정** 중 선택할 수 있습니다.
선택은 자동 저장되고, JSON 백업에도 포함됩니다. 이전 버전의 백업도 그대로 불러올 수 있습니다.
기본은 올리브 네이비·라이트입니다. 기존 일정과 지출 저장 키는 유지했습니다.

### 모바일 업로드에 맞춘 구성

**이 ZIP 안에는 하위 폴더가 없습니다.** 실행 파일, 아이콘, 안내서, 테스트 파일까지 모두 같은 최상위 위치에 있습니다. 압축 해제 후 파일 전체를 선택해 업로드하세요.
이미 GitHub에 v1.0.0을 올렸다면 이번 ZIP의 모든 파일을 같은 최상위 위치에 덮어씌우세요. 새 `appearance.js`, `themes.css`도 반드시 포함하세요.
업로드 후 기존 탭을 모두 닫고 다시 열거나 새로고침해 업데이트를 적용하세요.
저장소에서 기존 `test` 폴더를 정리하지 않아도 실행에는 영향이 없으며, 이번 버전에는 테스트 파일도 최상위로 옮겨져 있습니다.

## 1. GitHub 업로드·배포

1. ZIP을 압축 해제합니다.
2. GitHub에 새 저장소를 만듭니다. 예: `busan-pocket`.
3. **Add file → Upload files**에서 압축 해제한 폴더의 **내용물**을 업로드합니다.
4. `index.html`, `app.js`, `core.js`, `style.css` 등이 저장소 맨 위에 있어야 합니다. 폴더 자체나 ZIP만 업로드하지 마세요.
5. **Commit changes**로 저장합니다.
6. 저장소의 **Settings → Pages**로 갑니다.
7. **Build and deployment**를 아래처럼 설정하고 **Save**를 누릅니다.

   | 항목 | 설정 |
   |---|---|
   | Source | Deploy from a branch |
   | Branch | main |
   | Folder | / (root) |

8. 배포 완료 후 Pages 화면에 표시되는 사이트 주소를 엽니다.
   프로젝트 주소 예: `https://YOUR_NAME.github.io/busan-pocket/`

브랜치 이름이 `main`과 다르면 실제 업로드한 브랜치를 선택합니다.
계정 요금제에 따라 비공개 저장소의 Pages 사용 가능 여부가 달라질 수 있습니다.
Pages 설정이 없다면 저장소 권한과 계정의 Pages 지원 여부를 확인하세요.

`.nojekyll`은 빌드 없이 정적 파일을 배포하기 위한 빈 파일입니다. 숨김 파일이 업로드되지 않으면 Git으로 올리거나 GitHub의 **Add file → Create new file**에서 `.nojekyll` 파일을 추가하세요. 빈 파일 생성이 어려우면 `# Static site` 한 줄을 넣어도 됩니다.

공식 안내:
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site

## 2. 휴대폰에 설치

1. Android Chrome에서 배포된 HTTPS 주소를 엽니다.
2. 브라우저 메뉴의 **홈 화면에 추가** 또는 **앱 설치**를 선택합니다.
3. 추가된 아이콘으로 실행합니다.

`index.html` 파일을 직접 터치해 `file://`로 열면 모듈과 서비스 워커가 제대로 작동하지 않습니다. GitHub Pages 주소 또는 로컬 HTTP 서버를 이용하세요.
처음에는 온라인으로 앱을 열어 파일을 받아야 합니다. 이후 캐시된 화면을 오프라인에서도 사용할 수 있습니다. 캐시를 지우면 다시 온라인으로 접속해야 합니다.

## 3. 포함된 기능

- 현재·지난·다음 일정 자동 표시, 일정 사이의 자유시간 안내
- 자정을 넘기는 숙소 휴식 처리
- 일정 추가·수정·삭제, 시간 중복 방지
- 전체·카테고리별 예산 설정
- 지출 추가·수정·삭제, 날짜/카테고리 필터, 잔액·초과 금액 계산
- 한국 시간(Asia/Seoul) 기준, 약 10초마다 시간 상태 갱신
- 시간 미리보기, 여행 시작일 변경
- JSON 백업 내보내기·불러오기
- 실행 중 일정 전환 안내, 지원되는 브라우저의 기기 알림

예산과 지출은 비어 있습니다. 금액을 임의로 넣지 않았습니다.
원본의 10월 24일 21:00부터 ‘다음 날 아침’까지의 휴식은 10월 25일 09:00까지로 설정했으며, 앱에서 수정할 수 있습니다.

## 4. 기존 앱의 기록 옮기기

기록은 **해당 기기·브라우저의 localStorage**에 저장됩니다. 서버나 GitHub에 지출을 자동 업로드하지 않습니다. 로그인·기기 간 자동 동기화는 없습니다.

1. 기존 웹앱에서 설정 → **백업 내보내기**를 누릅니다.
2. 새 GitHub Pages 웹앱을 엽니다.
3. 설정 → **백업 불러오기**에서 받은 JSON을 선택합니다.
4. 교체 내용을 확인하고 **교체하기**를 누릅니다.

주소가 바뀌면 기존 저장 데이터는 자동으로 옮겨지지 않습니다. 브라우저 데이터 삭제, 기기 변경 전에도 백업해 주세요.
같은 GitHub Pages 출처(`https://YOUR_NAME.github.io`)에서 앱 사본을 여러 개 운영하면 저장 키 `busan-pocket-v1`을 공유합니다. 독립된 여행을 운영하려면 `app.js`의 `KEY` 값을 사본마다 다르게 바꾸세요.

공개 저장소·웹사이트에 포함된 기본 일정은 방문자가 볼 수 있습니다. 개인 지출 백업은 저장소에 업로드하지 마세요. `.gitignore`는 Git으로 추가할 때 백업 파일을 제외하지만 웹에서 직접 업로드한 파일까지 막지는 않습니다.

## 5. 알림 범위

설정에서 **일정 전환 알림 켜기**를 켜세요. 앱 실행 중 일정이 바뀌면 화면으로 알려드립니다. 기기 알림은 브라우저 지원 및 알림 권한이 필요합니다.
앱 종료, 화면 잠금, 백그라운드 일시 정지 중 정시 알림은 보장하지 않습니다. 서버 푸시나 Android 백그라운드 알람은 포함되지 않습니다.
시간 미리보기 중에는 실제 일정 전환 알림을 보내지 않습니다.

## 6. 로컬 실행·자동 검증 (선택)

앱 파일이 있는 폴더에서 Python 3로 실행합니다.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 엽니다.
설치와 서비스 워커는 HTTPS 또는 localhost 같은 보안 컨텍스트에서 사용합니다.

Node.js 18 이상이 있으면 추가 패키지 설치 없이 핵심 로직을 검증합니다.

```bash
npm test
```

검증 범위: 기본 일정·예산 기능에 더해 테마 저장·복원, 모드 전환, 기기 설정 연동, 잘못된 설정 복구, 저장 차단 처리, 창 간 동기화 및 네 팔레트의 글자 대비. 총 14개 자동 검증을 통과했습니다.
핵심 자동 검증은 통과했습니다. 제작 환경의 미리보기 제한으로 실제 브라우저 화면과 Android 설치·알림의 실기기 검증은 완료하지 못했습니다.

## 7. 파일 구성과 수정

| 파일 | 역할 |
|---|---|
| index.html | 페이지 기본 구조 |
| style.css | 반응형 디자인 |
| themes.css | 두 가지 테마의 라이트·다크 팔레트 |
| appearance.js | 테마 저장, 첫 화면 적용, 기기 밝기 연동 |
| app.js | 화면·입력·저장·알림·백업 |
| core.js | 기본 20개 일정, 시간·예산 계산 |
| manifest.webmanifest | 설치 이름·아이콘·설정 |
| sw.js | 오프라인 캐시 |
| icon.svg, icon-192.png, icon-512.png | 앱 아이콘 |
| core.test.mjs, appearance.test.mjs | 핵심 로직 자동 검증 |
| package.json | 선택적 자동 검증 명령 |
| .nojekyll | 정적 파일 배포 설정 |

기본 일정을 바꾸려면 `core.js`의 `raw`와 날짜 값을 수정합니다. 이미 방문한 기기는 저장된 일정이 우선이므로 앱에서 직접 수정하거나 백업을 불러오세요.
업데이트 시 `sw.js`의 `CACHE` 이름을 예를 들어 `busan-pocket-v1.2.0`로 바꾸고 변경 파일들을 함께 업로드하면 캐시를 새로 받을 수 있습니다. 탭을 모두 닫았다가 열어 확인하세요. 브라우저 데이터를 삭제하면 지출까지 지워질 수 있으므로 먼저 백업하세요.

이 ZIP은 GitHub Pages용 독립 배포본입니다. 기존 호스팅 식별자, 인증 토큰, Git 메타데이터, 원본 사진, 개인 지출 데이터는 포함하지 않습니다.

테마 선택 저장 키는 `busan-pocket-appearance-v1`입니다. 같은 출처에서 사본을 독립 운영한다면 `appearance.js`의 KEY도 함께 바꾸세요.
